
Step 1: Structural Anatomy of a Custom Container Format

Most custom compound file formats follow a nested architecture designed to pack multiple resources into a single file system archive wrapper:
text
+-------------------+-------------------+-------------------+-------------------+

|    FILE HEADER    | TABLE OF CONTENTS |  COMPRESSED DATA  |    DATA BLOCK     |
|   (Magic+Flags)   | (File Index/TOC)  |  (Resource 1)     |   (Resource 2)    |
+-------------------+-------------------+-------------------+-------------------+
Use code with caution.
• The Header (Fixed Offset): Located at the very beginning (0x00). Contains unique identifying bytes, a version indicator, and the count of total files inside.
• The Table of Contents (TOC): A master index list mapping out information for every embedded resource, specifically tracking: Filename string, Absolute File Offset, Compressed Size, and Decompressed Size.

Step 2: Step-by-Step File Format Analysis


1. Analyze the File Layout Statically (Hex View)

Open the custom file inside a hex editor like ImHex or HxD.
• Look at the first 4 bytes. If the application is called SuperGame, you might find a custom text magic sign like SGM1 (0x53474D31).
• Scroll down to find patterns of printable ASCII text strings representing internal asset paths (e.g., textures/hero.png). Note the precise starting offset of these text clusters.

2. Correlate with Binary File I/O Logic

To confirm how the application reads this format, load the application's executable binary inside a decompiler (Ghidra or IDA Pro) and trace file operation APIs:
• Look for APIs: fopen(), fread(), or Windows native ReadFile() variants.
• Locate the initialization block right after fread(). You will typically find a structural assignment pattern:c
fread(file_buffer, 1, 16, file_handle);
int file_count = *(int *)(file_buffer + 4); // Extracting file count from offset 0x04
Use code with caution.

Step 3: Automating Extraction with Python (struct)

Once the layout is mathematically verified, you can write a clean parser script in Python using the struct module to unpack the entire compound file structure.

The Proprietary Unpacker Engine

python
import struct
import io

def unpack_custom_archive(archive_path: str):
    """
    Parses a proprietary container archive layout dynamically,
    reads its inner Table of Contents, and extracts embedded files.
    """
    print(f"[*] Opening custom archive asset container: {archive_path}")
    
    with open(archive_path, "rb") as arch:
        # 1. Read and unpack the fixed 12-Byte master header block
        # Specification format layout: Magic String (4B), Version (4B), File Count (4B)
        header_bytes = arch.read(12)
        magic, version, file_count = struct.unpack("<4sII", header_bytes)
        
        print(f"  ├─ Magic Identifier : {magic.decode('ascii', errors='ignore')}")
        print(f"  ├─ Format Version   : {version}")
        print(f"  └─ Internal Files   : {file_count} entries found")
        
        # 2. Iterate through the Table of Contents entries to map metadata
        # Assume each index entry layout is exactly 24 bytes long: 
        # Filename (12B ASCII string padding), Absolute Data Offset (4B), Data Size (4B), Reserved Flags (4B)
        file_index_entries = []
        
        print("\n[*] Parsing Archive Table of Contents (TOC)...")
        for i in range(file_count):
            entry_bytes = arch.read(24)
            name_raw, data_offset, data_size, flags = struct.unpack("<12sIII", entry_bytes)
            
            clean_name = name_raw.decode('ascii').strip('\x00')
            file_index_entries.append({
                "name": clean_name,
                "offset": data_offset,
                "size": data_size
            })
            print(f"   ├── Found Resource: {clean_name} [Size: {data_size} Bytes at Offset: {hex(data_offset)}]")
            
        # 3. Resource Harvesting Layer (Carving files based on parsed index metadata)
        print("\n[*] Executing asset extraction routine...")
        for file_info in file_index_entries:
            # Jump straight to the absolute physical data offset point inside the file
            arch.seek(file_info["offset"])
            
            # Carve out the exact slice matching the size definition
            raw_file_payload = arch.read(file_info["size"])
            
            # Log successful file parsing
            print(f"   [EXTRACTED] Saved {file_info['name']} successfully.")
