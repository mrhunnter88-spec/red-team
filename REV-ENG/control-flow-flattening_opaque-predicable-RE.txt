Step 2: Step-by-Step Analysis and Deobfuscation Strategy

To reverse a flattened binary, engineers use a combination of static code analysis and Symbolic Execution to trace how the state variable changes.

1. Identify the Core Components

When looking at the flattened function inside a decompiler like Ghidra, isolate three elements:
• The State Variable: A local integer variable initialized right before the main loop.
• The Dispatcher: The master conditional loop (often a while(true) or switch(state)) that reads the state variable.
• The Real Blocks: The actual blocks of original code executing operational math, which conclude by manually changing the state variable to point to the next block.

2. Eliminate Opaque Predicates

Look for mathematical invariants designed to confuse you. For example:
• if ((y * (y + 1)) % 2 == 0) \(\rightarrow \) This is always true for any integer \(y\). You can safely delete the else path from your analysis.
• if (z * z < 0) \(\rightarrow \) This is always false for real numbers. You can delete the true path entirely.

Step 3: Automating Deobfuscation with Python (Triton / z3)

For complex binaries, analysts don't resolve the switch states manually. They write Python scripts using symbolic execution frameworks (like Triton or Angr) to track the state variable automatically and rebuild a clean binary.
Below is a conceptual Python simulation using a constraint-based approach to show how an analyst programmatically un-flattens a state machine and maps out the true execution order.
python
def symbolic_unflatten_solver():
    """
    Simulates a symbolic execution engine resolving a flattened state machine
    to map out the true execution path of a binary.
    """
    # 1. Emulate the scrambled state blocks found in the binary
    # Structure: { current_state: (operation_description, next_state) }
    blocks = {
        0xBAAD: ("Initialize variables", 0x1111),
        0x3333: ("Verify license payload", 0x9999),  # Terminal success block
        0x1111: ("Decrypt local string constants", 0x2222),
        0x2222: ("Perform mathematical key check", 0x3333)
    }
    
    # Locate the initial state variable constant found in the binary's entry
    current_state = 0xBAAD
    true_execution_flow = []
    
    print(f"[*] Starting symbolic trace from initial state: {hex(current_state)}")
    
    # 2. Symbolic tracking loop to automatically map states
    visited_states = set()
    
    while current_state in blocks:
        if current_state in visited_states:
            print("[-] Circular loop detected or infinite state trap hit.")
            break
            
        visited_states.add(current_state)
        block_action, next_state = blocks[current_state]
        
        # Log the discovered genuine block link
        true_execution_flow.append({
            "from_state": hex(current_state),
            "action": block_action,
            "to_state": hex(next_state)
        })
        
        # Transition to the next state tracked symbolically
        current_state = next_state

    # 3. Output the cleanly reconstructed execution layout
    print("\n[+] Reconstructed True Control Flow Graph Layout:")
    for step, block in enumerate(true_execution_flow, 1):
        print(f"  Step {step}: State {block['from_state']} -> Execute: '{block['action']}' -> Moves to: {block['to_state']}")

if __name__ == "__main__":
    symbolic_unflatten_solver()
Use code with caution.

Step 4: Advanced Static Deobfuscation Tools

If you are dealing with heavily obfuscated native binaries (such as those compiled with OLLVM - Obfuscator-LLVM), writing custom scripts from scratch can be time-consuming. Reverse engineers typically rely on proven automated frameworks:
• Barf-Project or Angr: Used to symbolically execute the binary, extract the true basic block relationships, and filter out the dispatcher code.
• Deflat (by FZXi): A widely used Python plugin specifically designed to resolve control flow flattening in compiled binaries automatically by patching the basic blocks to bypass the main switch statement entirely.

Restating the Core Solution Mechanics


✅ De-Flattening Resolution Rule

Defeating control flow flattening relies on identifying the master State Variable and the central Dispatcher loop. By using symbolic tracking tools or runtime tracing, you can extract the exact transitions between real blocks, discard dead code paths generated by Opaque Predicates, and patch the binary to jump directly from one functional block to the next.
