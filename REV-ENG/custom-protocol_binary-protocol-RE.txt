
Step 1: Structural Anatomy of a Binary Packet

Most binary protocols conform to a structured framing pattern. To parse the data stream, you must locate these elements:
text
+---------------+---------------+-------------------+-------------------+---------------+

|  MAGIC BYTES  |  PACKET LENGTH|    OPCODE (CMD)   |   PAYLOAD DATA    |   CHECKSUM    |
| (1-4 Bytes)   |  (1-4 Bytes)  |    (1-2 Bytes)    |  (Variable Size)  |  (1-4 Bytes)  |
+---------------+---------------+-------------------+-------------------+---------------+
Use code with caution.
• Magic Bytes (Preamble): Static values used to sync the receiver (e.g., 0x7E, 0x55AA).
• Packet Length: Tells the receiver exactly how many bytes to read next.
• Opcode: A numeric ID dictating what action to take (e.g., 0x01 = Login, 0x02 = KeepAlive).
• Checksum: A mathematical validation tail (CRC32, Adler32, or simple XOR) to ensure packet integrity.

Step 2: Step-by-Step Protocol Reversing Flow


1. Differential Traffic Analysis (Black-Box Approach)

Capture live communication using packet sniffers like Wireshark. Generate known actions to spot variable mutations:
• Send multiple identical requests (e.g., click "Login" with the same password three times). Note which bytes remain static (Headers/Magic Bytes) and which bytes change (Timestamps, Session IDs, or Checksums).
• Alter a single parameter incrementally (e.g., send the username "A", then "AA", then "AAA"). Watch how the length field value changes to track its exact byte location.

2. Correlating Traffic with Binary Logic (White-Box Approach)

Load the application binary sending or receiving the protocol into a disassembler (Ghidra/IDA Pro):
• Search for native socket communication functions like send(), recv(), write(), or sendto().
• Trace backwards from the buffer argument passed to send(). This leads to the Serialization Function where the app structures raw variables into bytes.
• Look for multi-branch structures (switch or if-else cascades) right after a recv() call. These handle incoming Opcodes.

Step 3: Automating Protocol Dissection with Python (Construct)

When working with custom binary streams, writing manual slice offsets (like data[4:8]) is error-prone. The construct Python library provides a powerful declarative parser to model and execute binary structure slicing.

The Python Protocol Parser Engine

python
from construct import Struct, Int8ub, Int16ub, Int32ub, Bytes, Array, this, Checksum
import zlib

# 1. Declare the exact structural layout discovered during analysis
CustomProtocolSpec = Struct(
    "magic" / Bytes(2),                  # 2 Bytes Sync Marker (e.g. b"PX")
    "length" / Int16ub,                  # 2 Bytes Unsigned Big-Endian Payload Length
    "opcode" / Int8ub,                   # 1 Byte Command Opcode
    "session_id" / Int32ub,              # 4 Bytes Session Identifier
    
    # Dynamically reads 'length' field to determine payload byte slice size
    "payload" / Bytes(this.length),      
    
    "crc32" / Int32ub                     # 4 Bytes Integrity Checksum Trailer
)

def parse_incoming_stream(raw_bytes: bytes):
    """Parses a raw incoming byte packet against our custom layout schema."""
    try:
        print(f"[*] Raw Byte Stream Received: {raw_bytes.hex().upper()}")
        
        # Parse raw bytes into an accessible, structured dictionary object
        parsed_packet = CustomProtocolSpec.parse(raw_bytes)
        
        print("\n[+] Reconstructed Protocol Fields:")
        print(f"  ├─ Magic Marker : {parsed_packet.magic}")
        print(f"  ├─ Length Field : {parsed_packet.length} bytes")
        print(f"  ├─ Opcode       : {hex(parsed_packet.opcode)}")
        print(f"  ├─ Session ID   : {parsed_packet.session_id}")
        print(f"  └─ Payload Data : {parsed_packet.payload.decode('utf-8', errors='ignore')}")
        
        # Verify Checksum Integrity
        # Extract data block excluding the 4-byte CRC trailer
        data_to_verify = raw_bytes[:-4]
        calculated_crc = zlib.crc32(data_to_verify) & 0xFFFFFFFF
        
        if calculated_crc == parsed_packet.crc32:
            print("[+] Packet Integrity: VALID (CRC Matches)")
        else:
            print(f"[!] Warning: Integrity Corrupted! Local CRC: {hex(calculated_crc)}, Packet CRC: {hex(parsed_packet.crc32)}")
            
    except Exception as e:
        print(f"[-] Parsing failed: Struct constraint violation. Details: {e}")

# --- Demonstration Run ---
if __name__ == "__main__":
    # Simulated captured network frame matching our custom specification layout:
    # Magic("PX") | Length(0x000B) | Opcode(0x05) | Session(0x10203040) | Payload("Hello World") | CRC32
    mock_network_frame = (
        b"PX" +                         # Magic
        b"\x00\x0B" +                   # Length (11 bytes payload)
        b"\x05" +                       # Opcode 5
        b"\x10\x20\x30\x40" +           # Session ID
        b"Hello World"                  # Payload Data
    )
    
    # Compute true CRC tail append to forge a valid payload packet stream
    true_crc = zlib.crc32(mock_network_frame) & 0xFFFFFFFF
    complete_packet = mock_network_frame + true_crc.to_bytes(4, byteorder='big')
    
    parse_incoming_stream(complete_packet)

Step 4: Writing a Custom Wireshark Dissector (Lua)

To view your custom protocol live in Wireshark with full variable breakdowns, write a Lua Dissector Script and save it into Wireshark's plugins/ directory.
lua
-- Define our custom protocol schema block
local my_proto = Proto("custom_proto", "My Custom Proprietary Protocol")

-- Define individual header variable parsing offsets
local f_magic   = ProtoField.string("custom_proto.magic", "Magic Marker")
local f_length  = ProtoField.uint16("custom_proto.length", "Payload Length", base.DEC)
local f_opcode  = ProtoField.uint8("custom_proto.opcode", "Opcode Command", base.HEX)
local f_payload = ProtoField.string("custom_proto.payload", "Payload String")

my_proto.fields = { f_magic, f_length, f_opcode, f_payload }

-- The core parser evaluation loop executed for every arriving frame packet
function my_proto.dissector(buffer, pinfo, tree)
    length = buffer:len()
    if length < 5 then return end -- Check minimum boundary packet header constraint
    
    pinfo.cols.protocol = "MY_PROTO"
    
    -- Instantiate the subtree layout view inside the Wireshark UI
    local subtree = tree:add(my_proto, buffer(), "Custom Protocol Data")
    
    -- Extract and map variable zones from exact packet index offsets
    subtree:add(f_magic,   buffer(0, 2))
    subtree:add(f_length,  buffer(2, 2))
    subtree:add(f_opcode,  buffer(4, 1))
    subtree:add(f_payload, buffer(5, length - 5))
end

-- Bind the Lua parser template to trigger on a specific network port (e.g. TCP port 9999)
local tcp_table = DissectorTable.get("tcp.port")
tcp_table:add(9999, my_proto)
