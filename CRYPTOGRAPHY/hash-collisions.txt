
💻 Category 1: Resolving Collisions in Data Structures (Coding)

In programming (e.g., building hash tables, dictionaries, or maps), collisions are an inevitable result of the pigeonhole principle. You resolve them at the architecture level using two core algorithms:

1. Separate Chaining (Linked Lists / Trees)

Instead of storing one value per index, each slot in the hash table points to a linked list (or a balanced binary tree, like Java 8's HashMap implementation) of entries that share that index.
python
class SimpleHashTable:
    def __init__(self, size=10):
        self.size = size
        self.table = [[] for _ in range(size)] # Array of lists (Separate Chaining)

    def insert(self, key, value):
        idx = hash(key) % self.size
        # Overwrite if key exists, otherwise append to resolve collision
        for kv in self.table[idx]:
            if kv[0] == key:
                kv[1] = value
                return
        self.table[idx].append([key, value])
Use code with caution.

2. Open Addressing (Linear Probing)

If a collision occurs at a targeted index slot, the system systematically searches for the next available empty slot in the array using an offset formula (e.g., (index + i) % size).

🧮 Category 2: Generating Cryptographic Collisions (MD5 / SHA-1)

In security engineering, older algorithms like MD5 and SHA-1 are completely broken due to mathematical shortcuts that find collisions exponentially faster than standard brute-force guessing.

Method 1: Generating Raw MD5 Collisions with md5collgen

You can use the native command-line tool md5collgen (based on Marc Stevens' HashClash framework) to create two distinct files with identical MD5 signatures instantly.
bash
# 1. Install the tool via standard Linux package managers
sudo apt install openssl clone tools -y   # Or build from source

# 2. Provide a prefix file (base data) and generate two colliding output binary files
echo "BasePrefixData" > prefix.txt
md5collgen -p prefix.txt -o sample_1.bin sample_2.bin
Use code with caution.
If you verify the results using your terminal tools, you will see that the files differ in their trailing bytes, but their hashes match perfectly:
bash
xxd sample_1.bin | head -n 3
xxd sample_2.bin | head -n 3 # Content will diverge structurally

md5sum sample_1.bin sample_2.bin
# Output:
# 78a1f2b3e4a5c6d7e8f90a1b2c3d4e5f  sample_1.bin
# 78a1f2b3e4a5c6d7e8f90a1b2c3d4e5f  sample_2.bin
Use code with caution.

Method 2: Exploiting identical suffixes (Chaining Property)

Because Merkle-Damgård hashes process messages in sequentially chained blocks, if two blocks collide, you can append the exact same data to both files and they will continue to collide indefinitely.
\(\text{If\ Hash}(A)==\text{Hash}(B)\implies \text{Hash}(A+\text{Suffix})==\text{Hash}(B+\text{Suffix})\)
bash
# Append a custom malicious payload script to both colliding structures
cat malicious_payload.py >> sample_1.bin
cat malicious_payload.py >> sample_2.bin

# The output files still maintain identical MD5 hashes!
md5sum sample_1.bin sample_2.bin
Use code with caution.

🛡️ Remediating Hash Collision Risks

If you are auditing system code or file verification structures from the terminal, enforce total mitigation against collision attacks using modern primitives:
• Ban Legacy Functions: Search the codebase for instances of md5 or sha1 being used to verify data integrity, file uploads, or password derivations.
• Mandate Collision-Resistant Hashes: Migrate entirely to SHA-256, SHA-512, or SHA-3. No mathematical collision has ever been found or generated for these algorithms, meaning the only way to cause a collision is a brute-force search requiring more energy than is available in the solar system.
