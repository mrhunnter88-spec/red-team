🐍 Method 2: Python Script (Brute-Force & English Score)

If you are working inside a CTF pipeline or do not want to install large NLP toolkits, copy and paste this Python 3 script directly into your terminal. It scores every key variant based on standard English character frequencies (favoring spaces, E, T, A, O, etc.) and prints only the top statistical match.
python
# Save as xor_solver.py or drop directly into your python3 terminal loop
import string

def english_score(text):
    # Standard character frequency weights for English text
    weights = {
        'a': .0817, 'b': .0149, 'c': .0278, 'd': .0425, 'e': .1270, 'f': .0222,
        'g': .0201, 'h': .0609, 'i': .0696, 'j': .0015, 'k': .0077, 'l': .0402,
        'm': .0240, 'n': .0674, 'o': .0750, 'p': .0192, 'q': .0009, 'r': .0598,
        's': .0632, 't': .0905, 'u': .0275, 'v': .0097, 'w': .0236, 'x': .0015,
        'y': .0197, 'z': .0007, ' ': .1300
    }
    return sum(weights.get(chr(b).lower(), 0) for b in text)

# Replace this with your target hex-encoded ciphertext
ciphertext_hex = "1c1e0b0c036d1b03120c046d21"
c_bytes = bytes.fromhex(ciphertext_hex)

best_score = 0
best_plaintext = ""
best_key = 0

# Test all 256 possible single-byte keys
for key in range(26):
    # Perform the XOR operation for the current key guess
    candidate = bytes(b ^ key for b in c_bytes)
    score = english_score(candidate)
    
    if score > best_score:
        best_score = score
        best_plaintext = candidate
        best_key = key

print(f"🎯 Best Match Found!")
print(f"Key (Hex)   : 0x{best_key:02x} (Decimal: {best_key})")
print(f"Plaintext  : {best_plaintext.decode(errors='ignore')}")
Use code with caution.

🐧 Method 3: Dumb Brute-Force Dump (Pure Bash/Zsh)

If you are on a bare-bones Linux system without access to Python libraries, you can run a pure terminal loop to dump all 256 possibilities into a text file, then search for common words like "the" or "flag".
bash
# Define your target hex string
HEX_STR="1c1e0b0c036d1b03120c046d21"

# Loop through all 256 potential keys, translating hex and printing lines
for key in {0..255}; do
  printf "Key 0x%02x: " "$key"
  echo "$HEX_STR" | xxd -r -p | python3 -c "import sys; print(''.join(chr(b ^ $key) for b in sys.stdin.buffer.read()).replace('\n', ' '))"
done > all_guesses.txt

# Inspect the output file or instantly grep for readable fragments
grep -i "the" all_guesses.txt || head -n 20 all_guesses.txt
Use code with caution.

🔍 Spotting Single-Byte XOR Markers

If you encounter an anonymous data payload during a network packet capture or a binary analysis, use these two terminal checks to verify if it is single-byte XOR:
1. Preserved Repeating Patterns: Because the key is only 1 byte long, any repeating pattern in the original plaintext remains a repeating pattern in the ciphertext. If a file contains a long string of repeating null bytes (0x00), the ciphertext will display a long sequence of the identical key byte repeating perfectly.
2. Index of Coincidence (IC): If you pass the ciphertext characters through an IC calculation script, a single-byte XOR string will yield an IC matching natural text (~0.06) rather than random distribution (~0.038). This is because the linear character spacing distances are entirely preserved; they are simply shifted uniformly.
