
🧬 Part 1: Code-Based Cryptography (McEliece/Niederreiter)

Code-based security relies on the hardness of decoding a generic linear code (the Syndrome Decoding Problem). The public key is a generator matrix \(G\) that has been intentionally obfuscated by scrambling matrices (\(S\)) and permutation matrices (\(P\)): \(G_{\text{pub}} = S \cdot G \cdot P\).
For toy parameters, you can bypass the structural obfuscation completely using an Information Set Decoding (ISD) attack, or reconstruct the underlying algebraic Goppa code trapdoor via the Support Splitting Algorithm.

Method 1: Executing Information Set Decoding (ISD) in SageMath

ISD works by randomly selecting a subset of columns from the public matrix that are error-free, computing an inversion, and checking if it yields a valid codeword. If the code size is small (e.g., \(n=100, k=50\)), it succeeds in seconds.
python
# Run this inside a SageMath terminal (sage)
from sage.coding.information_set_decoding import LeeBrickell

# 1. Load your toy public generator matrix (G) and captured ciphertext (c)
# Example parameters: Linear Code over GF(2)
F = GF(2)
G_pub = Matrix(F, [[1, 0, 1, 1], [0, 1, 0, 1]]) # Replace with your target public matrix
ciphertext = vector(F, [1, 1, 0, 1])
num_errors = 1

# 2. Set up a standard Linear Code object
C = LinearCode(G_pub)

# 3. Initialize the ISD solver (Prange, Lee-Brickell, or Stern algorithm variants)
isd_solver = LeeBrickell(C, num_errors)

# 4. Extract the clean plaintext error vector
try:
    error_vector = isd_solver.decode(ciphertext)
    plaintext = ciphertext - error_vector
    print(f"🎯 Successfully decoded!")
    print(f"Recovered Error Vector: {error_vector}")
    print(f"Recovered Plaintext: {plaintext}")
except ValueError:
    print("Decoding failed: Check the number of expected injected errors.")
Use code with caution.

📐 Part 2: Multivariate Cryptography (Rainbow / UOV)

Multivariate cryptography relies on the difficulty of solving a system of non-linear, quadratic polynomial equations over a finite field (the MQ Problem). The public key is a set of quadratic polynomials:
\(P_{1}(x_{1},\dots ,x_{n})=0,\quad P_{2}(x_{1},\dots ,x_{n})=0,\dots \)
When dimensions are small, you can crack these systems by computing a Gröbner Basis using the F4/F5 algorithms, or by executing a MinRank algebraic reduction to separate the "Oil" and "Vinegar" variable spaces.

Method 2: Solving Quadratic Systems via Gröbner Basis (SageMath)

If you have captured a signature or public system of equations with a toy number of variables (e.g., fewer than 30 variables), a Gröbner Basis computation will systematically linearize and solve the system.
python
# Run this inside a SageMath terminal (sage)

# 1. Define the Finite Field and Polynomial Ring variables
# Example: 4 variables over GF(31)
F = GF(31)
R.<x1, x2, x3, x4> = PolynomialRing(F, 4, order='lex')

# 2. Input your public multivariate polynomial system equations
# (Set each equation equal to its corresponding ciphertext output integer value)
eqs = [
    x1^2 + 3*x2*x3 + x4 - 12,
    2*x2^2 + x1*x4 + 5*x3 - 7,
    x3^2 + 4*x1*x2 + 2*x4 - 22,
    x4^2 + x2*x3 - x1 + 3
]

# 3. Create the Ideal generated by your equation system
I = R.ideal(eqs)

# 4. Compute the Gröbner Basis (Uses fast underlying C libraries like Singular/m4ri)
print("Computing Gröbner Basis...")
basis = I.groebner_basis()

# 5. Extract the explicit point solutions
solutions = I.variety()
print(f"🎯 System solved! Found valid variable assignments:")
print(solutions)
Use code with caution.

💻 Method 3: Auditing Public Parameter Sizes via CLI

If you are evaluating real-world production post-quantum deployments (such as Classic McEliece, a NIST post-quantum standard), you must ensure its parameters are securely scaled far away from these algebraic tool thresholds. You can inspect key parameters using command-line diagnostic scripts.
bash
# Example check: Parse a Classic McEliece Public Key file (.pub / .pem) 
# to inspect matrix dimensions and Galois Field scaling size
openssl pkey -pubin -in mceliece_pub.pem -text -noout | grep -E "bits|Field|Dimension"
Use code with caution.
• Vulnerable (Toy Parameter): Modulus profiles or parameters like \(n=256, m=8, t=10\). This configuration creates an easily factorable structural footprint.
• Secure (Production Standard): Production sizes map to ultra-dense matrices like McEliece 348864 (\(n=3488\), \(k=2728\), \(t=64\)) or McEliece 8192128 (\(n=8192\), \(k=6528\), \(t=128\)). At these structural dimensions, calculating a Gröbner Basis or spinning up an ISD algorithm matrix loop would require more compute cycles than the age of the universe.
