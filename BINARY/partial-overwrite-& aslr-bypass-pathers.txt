A Partial Overwrite is a highly efficient technique used to bypass ASLR and PIE without needing an information leak (infoleak).
When ASLR randomizes the memory map, it shifts the base address of the application and its libraries, but it does not randomize the relative positions of functions within the same memory segment. Furthermore, page-alignment rules mean that the lowest 12 bits (1.5 bytes) of a memory address never change.
By using a buffer overflow to overwrite only the lowest 1 or 2 bytes of the Saved Return Address, you can redirect execution to an adjacent function (like a hidden win() function) while leveraging the randomized base address already loaded into the CPU.

1. The Geometry of a Partial Overwrite (The 12-Bit Rule)

Memory pages are allocated in blocks of 4096 bytes (0x1000). Because of this, the lowest 3 hex digits (12 bits) of a function's address remain completely static across reboots.
Imagine the static offsets found in your disassembler are:
• vulnerable_function: 0x55555555**11a0**
• win: 0x55555555**11c5**
When ASLR randomizes the executable, the base shifts, turning the runtime addresses into something like:
• vulnerable_function: 0x560a3df9**11a0**
• win: 0x560a3df9**11c5**
Notice that the top bytes shift randomly, but the bottom byte (\xc5) remains completely fixed.

The 1-Byte Overwrite (No Brute-Force)

If the target function shares the exact same upper digits, you can perform a 1-byte overwrite. By writing just \xc5 into the lowest byte of the return address, you instantly redirect execution to win() without needing to know the rest of the randomized base address.

The 2-Byte Overwrite (The 4-Bit Brute-Force Dilemma)

If your target function sits slightly further away (e.g., ending in 0x22c5), you must overwrite 2 bytes (\x22\xc5).
• The lowest 12 bits (\x2c5) are static.
• The 4th hex digit (\x2) is part of the randomized ASLR space.
• This introduces a 4-bit guess (2⁴ = 16 possible combinations). Your exploit script must run in a loop, expecting to succeed statistically 1 out of 16 times.

# Context configuration
context.update(arch='i386', os='linux')

5. Defensive Architectural Rules Against Partial Overwrites

Because partial overwrites manipulate the lower, static offsets of execution frames, they are completely immune to standard ASLR. To stop them, developers must enforce strict compiler mitigations:
• Enable Position Independent Executable Padding: Modern compilers use PIE hardening to widen the relative compiler distance between code execution tracking frames and structural global functions, ensuring that jumping between functional boundaries requires cross-page overwrites that trigger a 4-bit or 12-bit randomized brute-force penalty.
• Activate Position Independent Stack Canaries: Enforcing stack protection flags (-fstack-protector-strong) ensures that even if you only want to overwrite a single byte of the return address, you cannot reach it without rewriting the stack canary tripwire first, resulting in an instant application crash.
