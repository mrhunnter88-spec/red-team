Analyzing an Android application for Fake Permission Abuse or Riskware-Style Alerts shifts the focus toward apps that use deceptive social engineering, misleading user interfaces, or continuous high-severity alert notifications. These applications (often categorized as Fleeceware, Scareware, or Riskware) do not always use technical code exploits. Instead, they exploit the Android user experience to force user actions, trick victims into granting overly broad system permissions, or scare them into paying for unnecessary premium subscriptions.

📂 Common Deceptive Visual Mechanics

When reverse engineering a scareware or riskware APK, look for these three major dark patterns:
1. Persistent Device Optimization Scares: The application implements hardcoded counter timers or fake system health scans. No matter the device state, it triggers an alarm alerting the user that their system is "infected" or "critically degraded" to force clicks on advertisement payloads or payment portals.
2. Permission Gatekeeping (Notification Abuse): Forcing users to accept critical background permissions (such as BIND_NOTIFICATION_LISTENER_SERVICE or SYSTEM_ALERT_WINDOW) by creating custom overlay screens that cover the UI until the user complies.
3. Fleeceware Billing Loops: Hidden or obscured web view frames that trigger premium SMS shortcode subscriptions or utilize Google Play billing APIs with confusing, high-cost subscription tiers masked behind a brief "free trial."

🛠️ Step-by-Step Reversing Methodology


Step 1: Scan for System Notification and Overlay Privileges

Decompile the APK file using Apktool or view its structure inside JADX-GUI. Search the AndroidManifest.xml for structural notification services or high-priority floating layout permissions:
• android.permission.SYSTEM_ALERT_WINDOW (Allows the app to display floating windows over all other apps—frequently abused by ransomware and scareware lockscreens)
• android.service.notification.NotificationListenerService (Allows the application to intercept and read all incoming system notifications, including OTP codes from banks)

Step 2: Audit Fake Scanning Engines

Look closely inside the Java logic for layout variables that manage alerts or warning text. If you find a scanning engine that relies on randomized timers rather than reading actual device telemetry data, it is a clear indicator of scareware:
java
public void onScanFinished() {
    // Hardcoded logic: Always flags an alert to scare the user
    int fakeThreatCount = new Random().nextInt(15) + 5; 
    this.statusText.setText("CRITICAL RISK: " + fakeThreatCount + " Viruses Found!");
    this.alertButton.setVisibility(View.VISIBLE);
}
Use code with caution.

🐍 Automation & Riskware Dark Pattern Harvesting with Python

The following Python script automates static signature scanning across a decompiled workspace. It parses configuration schemas for intrusive fullscreen overlay permissions and searches application classes for suspicious string keywords (e.g., hardcoded warning prompts) typically used to manufacture fake alerts.
python
import os
import re
import xml.etree.ElementTree as ET

def audit_riskware_indicators(decompile_dir):
    """Scans decompiled APK resources for scareware strings, overlay triggers, and billing hooks."""
    print(f"[*] Commencing Riskware and Dark Pattern audit inside: {decompile_dir}\n")
    
    manifest_path = os.path.join(decompile_dir, "AndroidManifest.xml")
    
    # 1. Flag high-risk user experience manipulation permissions
    ux_risk_permissions = {
        "android.permission.SYSTEM_ALERT_WINDOW": "Draw over other apps. Frequently abused to create un-dismissible scare screens.",
        "android.permission.BIND_NOTIFICATION_LISTENER_SERVICE": "Intercepts all incoming device notifications, allowing potential data or OTP theft.",
        "com.android.vending.BILLING": "Google Play Billing engine presence. Double-check for deceptive fleeceware models.",
        "android.permission.RECEIVE_BOOT_COMPLETED": "Ensures application persistence by starting background alerts immediately after the device boots."
    }

    if os.path.exists(manifest_path):
        try:
            ET.register_namespace('android', 'http://android.com')
            tree = ET.parse(manifest_path)
            root = tree.getroot()
            
            print("🚨 [UX Risk Permission Audit]")
            for perm in root.findall('.//uses-permission'):
                name = perm.attrib.get('{http://android.com}name')
                if name in ux_risk_permissions:
                    print(f"   [!] Flagged Privilege: {name}")
                    print(f"       Risk Vector:       {ux_risk_permissions[name]}")
            print("-" * 70)
        except Exception as e:
            print(f"[-] Error reading manifest structures: {e}")

    # 2. Check source logic for deceptive alert terminology and hardcoded scare tactics
    scareware_keywords = {
        "Hardcoded Danger / Infection Warnings": r'(?i)("system infected"|"virus found"|"battery critical"|"device compromised")',
        "Simulated Scanning Loop UI": r'FakeScan|SimulateScan|random.*nextInt',
        "Hidden Overlay Layer Instantiation": r'WindowManager\.LayoutParams|TYPE_APPLICATION_OVERLAY'
    }

    print("📊 [Scareware / Misleading UI Pattern Scan]")
    matches_found = 0
    
    for root, _, files in os.walk(decompile_dir):
        for file in files:
            if file.endswith((".java", ".smali", ".xml")):
                file_path = os.path.join(root, file)
                try:
                    with open(file_path, "r", encoding="utf-8", errors="ignore") as f:
                        content = f.read()
                        for label, regex in scareware_keywords.items():
                            if re.search(regex, content):
                                matches_found += 1
                                print(f"   [!] Component Flagged: {label}")
                                print(f"       File Location:     {os.path.relpath(file_path, decompile_dir)}")
                                print("       " + "-" * 40)
                except Exception:
                    continue
                    
    print(f"\n[+] Deceptive UX analysis complete. Total risks flagged: {matches_found}")

if __name__ == "__main__":
    # Path containing your apktool extracted file tree
    DECOMPILE_DIR = "decompiled_source"
    
    if os.path.exists(DECOMPILE_DIR):
        audit_riskware_indicators(DECOMPILE_DIR)
    else:
        print(f"[-] Directory '{DECOMPILE_DIR}' not found. Please provide a valid source folder path.")
Use code with caution
