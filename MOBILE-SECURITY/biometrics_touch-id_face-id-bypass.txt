Bypassing biometric authentication (Touch ID / Face ID / Fingerprint) in Android applications focuses on subverting how the app handles authentication callbacks. In mobile application security, biometric authentication can be implemented in two ways: Insecure (Cosmetic) or Secure (Cryptographic).
If an application implements biometric checks without linking them to cryptographic keys inside the hardware-backed keystore, you can completely bypass the authentication screen at runtime using dynamic instrumentation.

📂 The Two Forms of Biometric Architectures

Before writing a bypass, you must understand how the app treats a successful fingerprint match:
1. Cosmetic Authentication (Vulnerable): The app displays a fingerprint prompt. If you touch the sensor, a simple callback method (onAuthenticationSucceeded) triggers. It returns a generic boolean flag or executes an intent to transition to the main dashboard. This implementation is highly vulnerable to runtime hooking.
2. Cryptographic Authentication (Secure): A successful fingerprint match unlocks a private key housed securely inside the device's Android Keystore System. This key is then used to decrypt a critical session token. If you bypass the UI callback here, the application will crash or fail later because it never received the decrypted cryptographic token needed to communicate with the server.

🛠️ Step-by-Step Reversing Methodology


Step 1: Search for Biometric Callbacks

Decompile your target APK using JADX-GUI or extract it via Apktool. Open a global codebase search and target the official Android biometric architecture signatures:
• BiometricPrompt
• BiometricPrompt$AuthenticationCallback
• FingerprintManager (Legacy Android API, still common in older apps)

Step 2: Analyze the Success Trigger

Look closely at the onAuthenticationSucceeded method implementation inside the decompiled code. If you see it defined like this:
java
@Override
public void onAuthenticationSucceeded(BiometricPrompt.AuthenticationResult result) {
    super.onAuthenticationSucceeded(result);
    // Cosmetic check flag! No crypto object used.
    this.this$0.navigateToDashboard(); 
}
Use code with caution.
Because the method takes an AuthenticationResult object but doesn't pull a CryptoObject out of it to decrypt an auth payload, you can force this method to execute on command, skipping physical biometric validation entirely.
