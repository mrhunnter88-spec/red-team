Solving Mobile API Style Challenges shifts the goal from just breaking local app logic to using the mobile app as a map to find hidden or vulnerable backend endpoints. In these challenges, the app is merely a client interacting with an external API (REST, GraphQL, etc.). Vulnerabilities like BOLA (Broken Object Level Authorization), missing server-side validation, and hidden administrative endpoints are discovered by studying how the app communicates with the server.
Here is a step-by-step example and an automated Python script to identify and solve mobile API style challenges.

📂 Common API Vulnerabilities in Mobile Apps

When inspecting the API traffic generated by an APK, look for these three high-value flaws:
1. Broken Object Level Authorization (BOLA/IDOR): The app sends user identifiers in request headers or URLs (e.g., /api/v1/user/1004/profile). Changing 1004 to 1005 might reveal another user's private data because the backend fails to check if you own that resource.
2. Leaked API Keys and Documentation Paths: Developers often leave development server links, staging environments, or hidden documentation paths (like /api/swagger.json or /v1/graphiql) inside the client code.
3. Mass Assignment / Lack of Rate Limiting: Sending unexpected parameters to an endpoint (e.g., adding "is_admin": true to a profile update JSON body) or brute-forcing endpoints because the backend does not limit request volume.

🛠️ Step-by-Step Reversing Methodology


Step 1: Map the API Endpoints via Static Analysis

Before capturing live traffic, extract all endpoints hidden inside the strings or configuration files of the APK. Open the app in JADX-GUI and search for string patterns matching your target's domain structure or paths (e.g., http://, https://, or /api/v).

Step 2: Capture and Analyze the Signature Blocks

Intercept the traffic using your configured proxy (like Burp Suite). Pay attention to any custom headers. Many API challenges rely on mobile-specific security signatures, such as:
http
POST /api/v2/transfer HTTP/1.1
Host: ://challenge-target.com
X-App-Signature: d29mY2g0bDZkYTM5OGU0YmNjYg==
Content-Type: application/json

{"amount": 100, "to": "user_b"}
Use code with caution.
If you alter the "amount", the server will reject it with a 403 Forbidden: Invalid Signature message. This implies you must look back into the decompiled APK to figure out how X-App-Signature is computed (often a hash of the body combined with a hidden salt).

🐍 Automation & API Harvesting with Python

The following Python script automates Static API Harvesting. It scans the entire decompiled source directory for URLs, base API paths, and query string endpoints, then maps them into a clean report so you don't have to look through hundreds of code classes manually.
python
import os
import re

def harvest_api_endpoints(decompiled_dir):
    """Scans decompiled APK source code for URLs, endpoints, and hidden API structures."""
    print(f"[*] Starting API architecture harvest inside: {decompiled_dir}\n")

    # Regular expressions to catch URLs, paths, and API documentation indicators
    api_patterns = {
        "Full URL Endpoint": r'https?://[a-zA-Z0-9.-]+\.[a-zA-Z]{2,}(?:/[^\s"\']*)?',
        "Relative API Route Path": r'["\']/(?:api|v1|v2|v3)/[a-zA-Z0-9_./-]+["\']',
        "Hidden API Documentation Reference": r'(?i)(swagger\.json|api-docs|graphiql|graphql|openapi\.yaml)',
        "Custom Security Token Header": r'(?i)(X-API-Key|X-App-Sig|Authorization|Bearer\s)'
    }

    discovered_endpoints = {key: set() for key in api_patterns}

    # Walk through source files
    for root, _, files in os.walk(decompiled_dir):
        for file in files:
            if file.endswith((".java", ".smali", ".xml", ".json")):
                file_path = os.path.join(root, file)
                
                try:
                    with open(file_path, "r", encoding="utf-8", errors="ignore") as f:
                        content = f.read()
                        
                        for label, regex in api_patterns.items():
                            matches = re.findall(regex, content)
                            for match in matches:
                                # Clean string wrappers if relative route path matched
                                cleaned_match = match.strip("\"'")
                                discovered_endpoints[label].add(cleaned_match)
                except Exception:
                    continue

    # Print grouped results
    for label, items in discovered_endpoints.items():
        if items:
            print(f"📦 [Discovered: {label}]")
            for item in sorted(items):
                print(f"   -> {item}")
            print("-" * 70)

if __name__ == "__main__":
    # Path to the directory created by your decompilation step
    DECOMPILE_DIR = "decompiled_source"
    
    if os.path.exists(DECOMPILE_DIR):
        harvest_api_endpoints(DECOMPILE_DIR)
    else:
        print(f"[-] Directory '{DECOMPILE_DIR}' not found. Please specify a valid decompiled package.")
